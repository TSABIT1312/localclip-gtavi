# Previous Video Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redesign the existing workspace and trim previously stored video with source preview and precise timecodes.

**Architecture:** Keep the existing single-page app and FastAPI/render pipeline. Add an editor-source endpoint with absolute bounds, optional start/end on EditClip, and safe temporary extraction for rerenders. UI uses native video/range inputs and existing crop behavior.

**Tech Stack:** HTML, CSS, vanilla JavaScript, FastAPI/Pydantic, FFmpeg, unittest.

**Spec:** docs/superpowers/specs/2026-11-24-editor-design.md

## Global Constraints
- No new dependencies or remote API calls during verification.
- Preserve source files and old successful renders on failure.
- Output content range 1–60 seconds; source times are absolute seconds.
- Native keyboard-accessible controls, responsive layout, Indonesian copy.
- Do not commit unless requested.

## Review Focus
- Legacy clips lacking full source: return available local bounds, never fabricate full coverage.
- Repeated trims: preserve original source coordinate origin; never trim cumulatively.
- Captions crossing trim boundaries: shift and clamp, discard empty ranges.
- Failed renders: preserve prior metadata/output, release BUSY.
- Invalid/half-specified/nonfinite/out-of-bounds range: reject before queueing.
